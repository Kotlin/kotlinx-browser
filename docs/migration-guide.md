# Migration guide

This guide is for moving from the earlier kotlinx-browser (0.x), whose declarations were generated by dukat from a
2017–2019 snapshot of the specs, or from the `org.w3c.*` declarations bundled with Kotlin/JS (`kotlin-dom-api-compat`).

The declarations are now generated from current Web IDL (pinned `@webref/idl`), and one source set serves both
Kotlin/JS and Kotlin/Wasm. The packages (`org.w3c.dom`, `org.w3c.fetch`, …) are kept, but signatures follow today's
specs, so this is a source-breaking release on both targets. It is not binary-compatible with either predecessor.

Most code needs only new imports and a few call-site changes. The sections below go roughly from most to least
common.

## Kotlin/JS: turn off the bundled DOM declarations

The Kotlin Gradle plugin adds `kotlin-dom-api-compat` to every JS compilation. It declares the same `org.w3c.*` and
`kotlinx.browser` names, so with both on the classpath the names are ambiguous. In `gradle.properties`:

```properties
kotlin.js.stdlib.dom.api.included=false
```

Kotlin/Wasm needs no setting.

## Imports: types that moved package

Every declaration is in the package of the spec that defines it today. Some core types are defined by different specs
than in the old snapshot:

| Type | Was | Now |
|---|---|---|
| `Event`, `EventTarget`, `EventListener` | `org.w3c.dom.events` | `org.w3c.dom` |
| `MouseEvent`, `MouseEventInit`, `WheelEvent`, `WheelEventInit` | `org.w3c.dom.events` | `org.w3c.dom.pointerevents` |
| `DOMParser`, `XMLSerializer` | `org.w3c.dom.parsing` | `org.w3c.dom` |
| `ArrayBuffer`, `DataView`, `Int8Array` … `Float64Array`, `ArrayBufferView`, `BufferDataSource`, their indexers and `toXxxArray()` conversions | `org.khronos.webgl` | `kotlinx.browser.typedarrays` |

`UIEvent`, `KeyboardEvent`, `FocusEvent`, `InputEvent` and `CompositionEvent` are still in `org.w3c.dom.events`.

The typed arrays are ECMAScript built-ins, not WebGL, so they left `org.khronos.webgl` (KT-57303); the WebGL API
itself stays there. WebGL code imports both:

```kotlin
import kotlinx.browser.typedarrays.*
import org.khronos.webgl.*
```

There are no deprecated aliases in the old package: an alias and the class, star-imported from both packages, make
the name unresolvable.

```kotlin
// Before
import org.w3c.dom.events.Event
import org.w3c.dom.events.MouseEvent

// After
import org.w3c.dom.Event
import org.w3c.dom.pointerevents.MouseEvent
```

## Event listeners

`addEventListener` with a Kotlin function now returns a function that removes exactly that listener, with the same
options:

```kotlin
val remove = button.addEventListener("click") { event -> println(event.type) }
// later
remove()
```

The extension is in `org.w3c.dom`, next to `EventTarget`. Passing the same Kotlin function to the member
`removeEventListener(type, callback)` also works. `MediaQueryList.addListener` behaves the same way.

## Dictionaries: factory parameters and absent members

Dictionary factories (`EventInit(...)`, `RequestInit(...)`, `AddEventListenerOptions(...)`, …) take the inherited
fields first, least derived first, then the dictionary's own. The old order was the reverse, and a positional call can
compile with a different meaning:

```kotlin
AddEventListenerOptions(true)           // was passive = true, is now capture = true
AddEventListenerOptions(passive = true) // means the same in both
```

**Use named arguments with dictionary factories.**

Members you don't pass are now left out of the object instead of being set to `null`. Before, `EventInit(bubbles = true)`
produced `{bubbles: true, cancelable: null, composed: null}`, and JS converted `null` instead of using the member's
default. To set an explicit `null`, assign the property after creating the object.

## CSS properties: `CSSStyleProperties`

The per-property attributes (`color`, `alignContent`, …, 763 of them) are on `CSSStyleProperties`, as in current
CSSOM, not on `CSSStyleDeclaration`. `element.style`, `window.getComputedStyle(element)` and `CSSStyleRule.style`
already have that type, so `element.style.color = "red"` works unchanged. Code holding a `CSSStyleDeclaration` needs
the more specific type:

```kotlin
// Before
fun paint(style: CSSStyleDeclaration) { style.color = "red" }
// After
fun paint(style: CSSStyleProperties) { style.color = "red" }
```

Gone: properties of abandoned specs (`marquee*`, `mark*`, `navIndex`, `imeMode`, `phonemes`, `voicePitchRange`) and
dukat's placeholders (`_camel_cased_attribute`, …). The vendor-prefixed aliases (`webkitAlignContent`, …) are not
declared; use the standard name. `wordWrap`, `fontStretch` and `gridGap` are kept.

## Changed types

| Before | Now | Why |
|---|---|---|
| `dynamic`, `Any?` parameters (`Request(input)`, `Headers(init)`, `XMLHttpRequest.send(body)`, `SourceBuffer.appendBuffer(data)`, …) | Typed overloads (`String`, `Request`, `BufferDataSource`, …) or `JsAny` | `dynamic` does not exist on Wasm; unions become overloads |
| `append(vararg nodes: dynamic)` (also `prepend`, `before`, `after`, `replaceWith`, `replaceChildren`) | `append(vararg nodes: Node)`, `append(vararg nodes: String)` and `append()` | Mixing nodes and strings in one call needs two calls |
| `setTimeout(handler: dynamic, timeout, vararg arguments)` (also `setInterval`) | `setTimeout(handler: () -> Unit, timeout)` and `setTimeout(handler: String, timeout)` | The return value is ignored; capture values in the lambda instead of passing `arguments` |
| `Promise<Unit>` (JS), `Promise<Nothing?>` (Wasm) for `Promise<undefined>` | `Promise<JsAny?>` | One declaration for both targets |
| `Int` for IDL `long long` (`Blob.slice`, the offset of `drawElements`, `vertexAttribPointer`) | `Double` | A JS number; exact up to 2^53 |
| `MouseEvent.clientX`, `clientY`, `screenX`, `screenY`: `Int` (also in `MouseEventInit` and the inits extending it) | `Double` | Pointer events report sub-pixel positions; use `.toInt()` where an integer is needed |
| `getClientRects(): Array<DOMRect>` | `getClientRects(): DOMRectList` | As specified; `asList()` gives a `List` |
| `WebGLRenderingContextBase.createBuffer(): WebGLBuffer?` and the other `create*` | Not nullable | WebGL spec change |
| `Element.scroll*`, `Window.scroll*` returning `Unit` | Return `Promise<ScrollResult>` | CSSOM View change; ignoring the result is fine |
| `ImageOrientation.FLIPY` | `ImageOrientation.FLIP_Y` | Enum names now split camel case |
| Dictionary fields declared `open var` | `abstract var` | A Kotlin object implementing a dictionary interface must implement every field; use the factory instead |

## Typed arrays

- **Unsigned element types.** Elements of unsigned typed arrays now have unsigned types: `Uint8Array` and
  `Uint8ClampedArray` use `UByte`, `Uint16Array` uses `UShort`, `Uint32Array` uses `UInt`, for both `get` and `set`.
  They were `Byte`, `Short` and `Int`. On JS those held the unconverted JS number (`200` in a `Byte`), which broke
  comparisons and arithmetic; on Wasm they were wrapped (`-56`). This includes `ImageData.data`:

  ```kotlin
  val red: UByte = imageData.data[0]   // was Byte
  val value: Int = imageData.data[0].toInt()
  imageData.data[0] = 255u
  ```

- **`DataView` unsigned accessors are unsigned.** `getUint8`, `getUint16` and `getUint32` return `UByte`, `UShort`
  and `UInt`, and `setUint8`, `setUint16` and `setUint32` take them; they were `Byte`, `Short` and `Int`, so
  `getUint8` of 200 was 200 in a `Byte` on JS and -56 on Wasm. They are extensions now, so code
  calling them needs the package import (`import kotlinx.browser.typedarrays.*` covers it). The signed and float accessors are unchanged.
- **`subarray()` and `subarray(start)`.** Both parameters of `subarray` are optional, as in JS.
- **`TypedArray<Self>`, a common interface of the nine typed arrays.** It has `length`, `set` and `subarray`, so one
  function can take any of them (`fun checksum(data: TypedArray<*>)`). The constructor taking an array and
  `set(array, offset)` accept any typed array, converting each element as JS does (`Int16Array(uint8Array)`); they
  took only the same type. It is an interface because `%TypedArray%` has no global, so `x is TypedArray<*>` is not
  available; check for the concrete type.
- **Kotlin/JS: no unsigned overloads taking a signed Kotlin array.** `Uint8Array(Array<Byte>)`,
  `Uint8ClampedArray(Array<Byte>)`, `Uint16Array(Array<Short>)`, `Uint32Array(Array<Int>)` and their
  `set(array, offset)` are removed: a clamped array turned every negative `Byte` into 0, so it could not hold 128–255.
  Use the conversions, which exist on both targets:

  ```kotlin
  val pixels = ubyteArrayOf(255u, 128u, 0u, 255u).toUint8ClampedArray()   // was Uint8ClampedArray(arrayOf<Byte>(...))
  ```

  `Uint8ClampedArray.toUByteArray()` and `UByteArray.toUint8ClampedArray()` are new. The signed and `Float32Array`
  overloads stay.

- **Conversions copy on JS.** `toByteArray()`, `toInt8Array()`, `toFloat32Array()`, … and their unsigned versions
  always return a new array containing exactly the elements of the view (`byteOffset`, `length`), as on Wasm. On JS
  the signed ones used to return the same object, so writes went to both. The unsigned ones used to convert the
  whole underlying buffer, ignoring the view, and did not compare equal (KT-79776).

## WebGL

- The constants are available as before, on `WebGLRenderingContext`, `WebGL2RenderingContext` and
  `WebGLRenderingContextBase`.
- `bufferData`, `bufferSubData`, `texImage2D`, `texSubImage2D`, `compressedTex*`, `readPixels`, `uniform*fv` and
  `uniformMatrix*fv` moved from `WebGLRenderingContextBase` to `WebGLRenderingContextOverloads`, because WebGL 2 has
  different overloads for them. They are still members of `WebGLRenderingContext`. Code typed against
  `WebGLRenderingContextBase` to share WebGL 1 and 2 needs the concrete type for these calls.

## Members that moved to a mixin or base type

These are still available on the same objects, so most code compiles unchanged. A value whose declared type is the old
holder no longer has them:

- `Range.startContainer`, `endOffset`, `collapsed`, … → `AbstractRange`
- `HTMLElement.focus()`, `blur()`, `tabIndex`, `dataset`, `autofocus`, `nonce` → `HTMLOrSVGOrMathMLElement`
- `Window.requestAnimationFrame`, `cancelAnimationFrame` → `AnimationFrameProvider`
- `MessagePort.onmessage`, `Worker.onmessage` → `MessageEventTarget`
- `KeyboardEvent.which` → `UIEvent`
- URL parts of `HTMLHyperlinkElementUtils` (`hash`, `host`, `pathname`, …) → `HyperlinkElementUtils`
- `SVG_UNIT_TYPE_*` on SVG elements → `SVGUnitTypes`
- `CacheQueryOptions.cacheName` → `MultiCacheQueryOptions`

## Removed because the specs removed them

Declarations that are no longer in any spec are not generated. The most likely to be in use, with replacements:

| Removed | Use instead |
|---|---|
| `Navigator.getUserMedia` | `navigator.mediaDevices.getUserMedia(constraints)` |
| `ApplicationCache`, `Window.applicationCache` | Service workers (`org.w3c.workers`) |
| `Document.createTouch`, `createTouchList` | `Touch(TouchInit(...))`, `TouchEvent(type, TouchEventInit(...))` |
| `Blob.close`, `isClosed` | — |
| `Notification.sound`, `sticky`, `noscreen` | — |
| `Request.type`, `RequestType`, `Response.trailer` | — |
| `URL.domainToASCII`, `domainToUnicode` | — |
| `HTMLAppletElement`, `HTMLKeygenElement`, `HTMLMenuItemElement`, `HTMLElement.contextMenu`, `dropzone` | — |
| `CanvasHitRegion`, `HitRegionOptions`, `CanvasDrawPath.resetClip` | — |
| SVG 2 mesh, hatch and solid-color elements, `SVGZoomAndPan`, `SVGUnknownElement` | — |
| `ondragexit`, `onshow`, `onloadend` on `GlobalEventHandlers` | — |
| `ImageOrientation.NONE`, `RequestDestination.MEDIA`, `RequestDestination.SERVICEWORKER` | — |

`SVGNameList` (and its indexer) and the foreign-fetch service-worker API are gone too.

## `kotlinx.dom` helpers removed

The `kotlinx.dom` extensions are gone. They predate APIs every browser now has; use those directly:

| Removed | Use instead |
|---|---|
| `element.addClass("a", "b")`, `removeClass(...)` | `element.classList.add("a", "b")`, `classList.remove(...)` |
| `element.hasClass("a")` | `element.classList.contains("a")` |
| `document.createElement("div") { ... }` | `(document.createElement("div") as HTMLDivElement).apply { ... }` |
| `element.appendElement("p") { ... }` | `element.append(document.createElement("p").apply { ... })` |
| `element.appendText("x")` | `element.append("x")` |
| `node.clear()` | `element.replaceChildren()`, or `node.textContent = ""` |
| `node.isElement`, `node.isText` | `node is Element`, `node is Text`, or `node.nodeType == Node.ELEMENT_NODE` |

`kotlinx.browser` (`window`, `document`, `localStorage`, `sessionStorage`) stays.

## Kotlin/Wasm: casts to external classes

On Wasm, casting to an external class (`x as CSSStyleProperties`, or a generic `T` bound to one) is an `instanceof`
check against that class's JS global, and it throws if the browser has no such global. Some newer names, such as
`CSSStyleProperties`, are not exposed by every browser yet. Where the object is known to be of the right kind, use
`unsafeCast<T>()`. Ordinary member access does not check anything.

## New in this version

- About 200 declarations the old snapshot did not have, among them Streams, `AbortController`, `OffscreenCanvas`,
  WebGL 2, the Navigation API, `ElementInternals`, the HTML Sanitizer API and popovers.
- APIs the old version did not cover at all, each in its own package: Web Animations (`org.w3c.animations`,
  `element.animate(...)`), Web Crypto (`org.w3c.webcrypto`, `window.crypto`), IndexedDB (`org.w3c.indexeddb`),
  Gamepad (`org.w3c.gamepad`), Web Audio (`org.w3c.webaudio`) and Encoding (`org.w3c.encoding`,
  `TextEncoder`, `TextDecoder`) and CSS Font Loading (`org.w3c.css.fonts`, `FontFace`, `document.fonts`).
- `on…` handlers typed with the event actually fired: `onclick: ((PointerEvent) -> Unit)?`.
- `operator get`/`set` for every indexed and named getter and setter.
- One source set for JS and Wasm. Code written against `webMain` compiles for both targets.
