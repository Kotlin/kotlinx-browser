# AGENTS.md

Instructions for coding agents working in this repository. Start with [docs/development.md](docs/development.md) for
the architecture, the commands and the reasons behind them. This file is the short version, plus the rules that are
easy to break.

## The project in one paragraph

kotlinx-browser is Kotlin `external` declarations for browser APIs, for Kotlin/JS and Kotlin/Wasm from one `webMain`
source set. The declarations in `src/webMain/generated/` are generated by the JVM generator in `generator/` from
pinned, committed webref inputs (`webref-idl.json`, `webref-events.json`, `webref-css.json`). The pipeline is
front-end → surface → lowerings → backend. Hand-written code is limited to `kotlinx.browser`, `kotlinx.dom`, the
typed-array built-ins and `JsObjects.kt`.

## Rules

1. **Never edit generated output by hand:**
   - `src/webMain/generated/**`
   - `src/*/kotlin/arrayCopy*.kt` and `src/webTest/kotlin/arrayCopyTest.kt`
   - `api/kotlinx-browser.klib.api`
   - `surface-report.txt`
   - `idl/`, `webref-*.json`
   - the goldens in `generator/src/test/resources/golden/`

   Change the generator or its inputs, then regenerate. Tests fail on any drift.
2. **Every generator change is followed by the full regeneration sequence** and a review of the resulting diffs:
   ```shell
   ./gradlew :generator:generateWebApi
   ./gradlew :generator:test -PupdateGolden=true
   ./gradlew updateKotlinAbi
   ./gradlew check
   ```
   The ABI diff is what users see. Read it, and explain it when reporting.
3. **Don't silence failures.** Generation fails on unresolved references, name clashes, unknown constant literals and
   stale exclusions on purpose. Fix the cause, or add a narrow, named, tested exception (see `NOT_INDEXERS`,
   `EXCLUDED_SPECS`). Never use a broad `@Suppress`. The only generated suppression is
   `COMPANION_OBJECT_IN_EXTERNAL_INTERFACE`, on companions.
4. **Interop claims need a runtime test.** If a generated shape relies on how JS or Wasm behaves at runtime, add a
   test to `src/webTest/kotlin/InteropTest.kt`. It runs on Node for both targets. Node has no DOM: use plain objects
   or install globals with `js(...)`. Several "obvious" shapes turned out wrong only at runtime (see below).
5. **Generated output must be deterministic:** no clock, no `System.lineSeparator()`, no map iteration order that
   isn't sorted or insertion-ordered. Headers come from `generatedFileHeader` in
   `generator/src/main/kotlin/helpers/header.kt`.
6. **Follow the spec.** Each definition goes into its spec's package and members go where the IDL puts them.
   Legacy (dukat-era) shapes are not a reason to diverge; when a spec change breaks users, record it in
   [docs/migration-guide.md](docs/migration-guide.md).
7. **Keep the docs in step:** add a user-visible break to the migration guide, and a new command, input or check to
   `docs/development.md`.
8. **Don't commit, push or bump webref versions** unless asked. Bumping is a reviewed chore (see "Bumping webref" in
   the development guide).

## Where to change what

| To change | Edit |
|---|---|
| Which specs are generated, their packages, exclusions | `generator/src/main/kotlin/idl/Specs.kt` |
| How IDL types map to Kotlin types | `generator/src/main/kotlin/idl/mapping/WasmTypeMapping.kt` |
| Class/interface/object shape, copied constants and statics, supertypes | `generator/src/main/kotlin/idl/lowering/Shapes.kt` |
| `override`/`open`, members inherited through several paths, dropped clashes | `generator/src/main/kotlin/idl/lowering/Overrides.kt` |
| Union handling | `lowering/UnionMarkers.kt`, `lowering/ExpandUnionOverloads.kt` |
| Event handler types (`onclick: (PointerEvent) -> Unit`) | `lowering/EventHandlerTypes.kt` |
| How anything is printed | `generator/src/main/kotlin/idl/backend/KotlinBackend.kt` |
| Inputs outside Web IDL (CSS properties, events) | `generator/src/main/kotlin/idl/frontend/WebrefCss.kt`, `WebrefEvents.kt` |
| Helpers the generated code calls (`newJsObject`, `getProperty`, …) | `src/webMain/kotlin/kotlinx/dom/JsObjects.kt` |

## Verifying a change

- `./gradlew check` must pass. It includes the generator tests, the up-to-date checks of the generated files, the
  goldens, `jsNodeTest`, `wasmJsNodeTest` and `checkKotlinAbi`.
- For a backend change, also compile the whole surface. `check` does this, but read the warnings: a new kind of
  compiler warning in generated code is a regression.
- When comparing with the old API, the dukat-era ABI dump is `git show 7098b12^:api/kotlinx-browser.klib.api`.

## Runtime facts that shaped the generator

- An `external interface`'s companion is **not read on Wasm** (values are `0`) and on JS needs a global named after
  the interface. Interface constants are therefore `inline` extensions holding the IDL value.
- On Wasm, casting to an external class is an `instanceof` check against its JS global, which may not exist. Use
  `unsafeCast` in tests and helpers.
- On Wasm, the declared types of a `js()` function decide the conversion at the boundary, so `JsObjects.kt` has one
  helper per key and value kind.
- Dictionary factories must omit absent members. JS treats `null` differently from "missing".
- Node 22.0–26.2 does not remove capture event listeners. That is a Node bug, so don't assert on it.
- Gradle only reruns `:generator:test` when its declared inputs change. The committed files it reads are declared in
  `generator/build.gradle.kts`; add any new one there.

## Style

- Kotlin official style, explicit `public` on top-level library declarations, KDoc on non-obvious generator code saying why, not what.
- Source files start with the Apache 2.0 header that points to "the LICENSE file".
- Tests: small IR via `LoweringTestDsl` for a single pass; `Real*Test` for facts about the pinned corpus; goldens for
  printed output.
